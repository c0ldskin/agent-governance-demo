How it works

Each layer is built here from tools already on this Mac. Step 2 replaces them with a platform such as NVIDIA OpenShell.

Layer (built here)What it doesEquivalent in OpenShell (step 2)
OS sandbox
macOS Seatbelt via sandbox-exec, one profile per agent		Each agent process can reach only the gateway's local port, read only its own folder, and can't read the credentials filePer-agent sandbox (MicroVM or container)
Governance gateway
a small local HTTP proxy in Python		Every agent request goes through it; default deny; YAML policy per agent with method and path rulesNetwork policy with layer-7 rules
Credential broker
inside the gateway		Holds the API key and adds it only to requests the policy allows; agents never see itCredential providers
Inference routing
inside the gateway		Model calls allowed only to the local OllamaInference provider routing
Policy as code
YAML in git, with a risk check		Diff, automatic flag on new destinations or credentials, human approval, commit, live reloadPolicies with live updates and the policy prover
Orchestrator delegation checkRefuses handoffs that ask an agent to do what the requester can'tBeyond OpenShell: agent identity and delegation
Audit and tracesStructured log of every decision (OCSF-like JSON), plus OpenTelemetry spans per agent step, linked by trace IDSandbox logs (OCSF)

Honest limits

  • Seatbelt isolates processes, which is weaker than VM isolation.
  • Apple has deprecated sandbox-exec. It still works and is widely used.
  • The gateway is demo-grade. It shows the pattern; production uses a hardened platform. That is the bridge to step 2.
